ติดตั้ง TuneLab Frontend–Backend บน Ubuntu

ห้ามใช้ image เดิมจนกว่าจะ rebuild: image ปัจจุบันฝัง Supabase project ที่ไม่สามารถ resolve DNS ได้ จึง login และ signup ไม่ได้

1. สร้าง Supabase project ของคุณ

  1. สร้าง hosted project ที่ Supabase Dashboard และเก็บ Project ref, Project URL, publishable key และ database password
  2. ใน Authentication → URL Configuration ตั้ง Site URL เป็น https://life-crawling-giver.ngrok-free.dev
  3. เพิ่ม Redirect URL https://life-crawling-giver.ngrok-free.dev/dashboard
  4. ใน Authentication → Providers → Email เปิด signup และ Confirm Email

จากเครื่องที่มี source frontend ให้ apply schema:

supabase login
supabase link --project-ref <PROJECT_REF>
supabase db push --dry-run
supabase db push
supabase migration list

migration สุดท้ายต้องเป็น 20260813000000_disable_demo_user_seed.sql เพื่อไม่สร้างข้อมูล demo ให้ผู้ใช้จริง

2. ตั้ง Google OAuth

  1. สร้าง OAuth 2.0 Client แบบ Web application ใน Google Cloud Console
  2. เพิ่ม Authorized redirect URI เป็น https://<PROJECT_REF>.supabase.co/auth/v1/callback
  3. นำ Client ID และ Client Secret ไปใส่ใน Supabase → Authentication → Providers → Google
Google Client Secret และ Supabase service_role key ต้องไม่ใส่ใน frontend, Docker build args หรือ Git

3. ตรวจ Supabase และ build frontend image

ตั้งไฟล์ .env ในโฟลเดอร์ frontend:

VITE_SUPABASE_PROJECT_ID="<PROJECT_REF>"
VITE_SUPABASE_PUBLISHABLE_KEY="<PUBLISHABLE_KEY>"
VITE_SUPABASE_URL="https://<PROJECT_REF>.supabase.co"
VITE_ENGINE_HOST=""
VITE_ENGINE_PROXY_TARGET="http://localhost:8088"
npm run check:supabase

docker build --pull \
  --build-arg VITE_ENGINE_HOST= \
  --build-arg VITE_SUPABASE_PROJECT_ID="<PROJECT_REF>" \
  --build-arg VITE_SUPABASE_PUBLISHABLE_KEY="<PUBLISHABLE_KEY>" \
  --build-arg VITE_SUPABASE_URL="https://<PROJECT_REF>.supabase.co" \
  -t sady567/slm-frontend:<VERSION> \
  -t sady567/slm-frontend:latest .

docker push sady567/slm-frontend:<VERSION>
docker push sady567/slm-frontend:latest

4. ตั้ง backend environment

แก้ slm-finetune-platform-dem/.env โดยให้ Supabase URL ตรงกับ frontend:

SUPABASE_URL=https://<PROJECT_REF>.supabase.co
SUPABASE_JWT_AUDIENCE=authenticated
SUPABASE_JWT_SECRET=
AUTH_REQUIRED=false
API_CORS_ORIGINS=https://life-crawling-giver.ngrok-free.dev
API_ALLOWED_HOSTS=life-crawling-giver.ngrok-free.dev,localhost,127.0.0.1,api,slm-api,slm-edge

เริ่ม backend และตรวจ health ก่อน:

cd slm-finetune-platform-dem
docker compose up -d
docker compose ps
curl -fsS http://127.0.0.1:8088/health

5. Pull และ run frontend

Frontend ต้องอยู่ network เดียวกับ backend และส่ง API ผ่าน slm-edge เพื่อคง rate limits:

docker pull sady567/slm-frontend:latest
docker rm -f slm-frontend 2>/dev/null || true

docker run -d \
  --name slm-frontend \
  --restart unless-stopped \
  --network slm-platform_slm-net \
  -e ENGINE_UPSTREAM=slm-edge:80 \
  -e ENGINE_UPSTREAM_HOST=edge \
  -p 127.0.0.1:8082:8080 \
  sady567/slm-frontend:latest
docker exec slm-frontend getent hosts slm-edge
curl -fsS http://127.0.0.1:8082/health
curl -I http://127.0.0.1:8082/

6. เปิดผ่าน ngrok

ngrok http --domain=life-crawling-giver.ngrok-free.dev 8082
curl -fsS https://life-crawling-giver.ngrok-free.dev/health

7. เปิดบังคับ JWT หลัง smoke test

  1. สมัครด้วยอีเมล ต้องเห็นหน้ารอยืนยันและได้รับอีเมล
  2. ยืนยันอีเมลแล้ว login และเปิด dashboard
  3. สร้าง project และยืนยันว่า request ไป /api/v1 ไม่ได้ 401
  4. ทดสอบ Google login และ WebSocket training progress
  5. เปลี่ยน backend เป็น AUTH_REQUIRED=true แล้ว restart API/worker
docker compose up -d --force-recreate api worker worker-cpu

# ต้องได้ 401 เมื่อไม่มี JWT
curl -i https://life-crawling-giver.ngrok-free.dev/api/v1/projects

Troubleshooting

docker logs --tail 200 slm-frontend
docker logs --tail 200 slm-edge
docker logs --tail 200 slm-api
docker compose config
docker network inspect slm-platform_slm-net
  • ERR_NAME_NOT_RESOLVED: Project URL ผิดหรือ Supabase project ใช้งานไม่ได้
  • redirect URL not allowed: Site URL/Redirect URL ใน Supabase ไม่ตรง ngrok domain
  • 401 invalid token: Backend และ frontend ใช้คนละ Supabase project หรือ JWKS ติดต่อไม่ได้
  • 502 Bad Gateway: frontend container resolve slm-edge ไม่ได้หรืออยู่คนละ Docker network
