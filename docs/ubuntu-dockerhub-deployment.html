คู่มือปัจจุบัน: Build frontend Docker image และ Push ขึ้น server

หัวข้อนี้ใช้กับ smart-model-tune-main รุ่นที่ login ผ่าน Keycloak และเก็บบัญชีใน PostgreSQL
ห้ามใส่ AUTH_DB_PASSWORD หรือ KEYCLOAK_ADMIN_PASSWORD ใน Docker build args, image หรือ Git ให้เก็บเฉพาะไฟล์ environment บน server
สถานะ 2 ต.ค. 2026: push sady567/slm-frontend:2026-10-02-postgres-1 สำเร็จและ pull ลง Ubuntu แล้ว รัน image รุ่นนี้แยกที่ 127.0.0.1:8083 เพื่อทดสอบ; เว็บจริงที่ 127.0.0.1:8082 ยังใช้ image รุ่นเดิม เพราะ Engine production ยืนยันตัวตนด้วย Supabase JWT และบัญชีทดสอบยังอยู่ที่ Supabase การสลับ production ต้องเตรียม Keycloak, ย้ายบัญชี/ความเป็นเจ้าของข้อมูล และรองรับ token ทั้งสองระบบหรือแยก backend ก่อน

ผลทดสอบบน Ubuntu และจุดตรวจรับก่อนสลับ production

image รุ่นใหม่ตอบหน้าแรกและ /health ที่พอร์ตทดสอบด้วย HTTP 200; /api/v1/projects ที่ไม่มี token ตอบ 401 ตามคาด ส่วน /auth/realms/tunelab/.well-known/openid-configuration ยังไม่ได้เป็น JSON ของ Keycloak จึงยังใช้การ login รุ่นใหม่ไม่ได้ ขณะเดียวกันเว็บจริงล็อกอินด้วยบัญชีทดสอบเดิมและโหลด projects, models, trainings, tasks ผ่าน Engine ได้ HTTP 200

docker image inspect sady567/slm-frontend:2026-10-02-postgres-1 --format '{{.Id}}'
docker ps --filter name=slm-frontend --format '{{.Names}} {{.Image}} {{.Ports}}'
curl -I http://127.0.0.1:8083/
curl -i http://127.0.0.1:8083/health
curl -i http://127.0.0.1:8083/auth/realms/tunelab/.well-known/openid-configuration

ก่อนสลับ ngrok มาที่ image ใหม่ ต้องได้ JSON จาก OIDC discovery, login ด้วยบัญชีที่ย้ายแล้วสำเร็จ และ API ของบัญชีนั้นตอบ 200 พร้อมข้อมูลเดิม; อย่าใช้ผล /health อย่างเดียวตัดสิน

ขั้นที่ 1 — Build และ Push image จากเครื่องที่มี source

เปิด Terminal ในโฟลเดอร์ frontend แล้วแทน <DOCKERHUB_USER> ด้วยชื่อ Docker Hub ของคุณ:

cd smart-model-tune-main

# ตรวจว่า source build ได้ก่อน
npm ci
npm run build

# ตั้งชื่อ release ที่ย้อนกลับไปใช้ได้
export VERSION=20261002.1
export DOCKERHUB_USER=your-dockerhub-username
export IMAGE="$DOCKERHUB_USER/tunelab-frontend"

# Login Docker Hub (ใช้ personal access token ได้)
docker login

# VITE_* ด้านล่างเป็นค่า public OIDC เท่านั้น ไม่มีรหัสผ่านฐานข้อมูล
docker build --pull \
  --build-arg VITE_ENGINE_HOST= \
  --build-arg VITE_AUTH_URL=/auth \
  --build-arg VITE_AUTH_REALM=tunelab \
  --build-arg VITE_AUTH_CLIENT_ID=tunelab-web \
  -t "$IMAGE:$VERSION" \
  -t "$IMAGE:latest" \
  .

# ตรวจ image และ push ทั้ง tag release กับ latest
docker image inspect "$IMAGE:$VERSION" --format '{{.Id}} {{.Size}}'
docker push "$IMAGE:$VERSION"
docker push "$IMAGE:latest"

Deploy ด้วย tag แบบ version เสมอ เช่น 20261002.1; latest ใช้เพียงบอกว่า release ล่าสุดคืออะไร

ขั้นที่ 2 — เตรียม server ครั้งแรก

SSH เข้า server แล้วนำ docker-compose.production.yml และ docker/keycloak/tunelab-realm.json จาก source ไปวางใน ~/tunelab-main ผ่าน Git, SCP หรือวิธีส่งไฟล์ที่ใช้อยู่:

mkdir -p ~/tunelab-main/docker/keycloak
cd ~/tunelab-main

# ต้องมีครบก่อนเริ่ม service
ls docker-compose.production.yml docker/keycloak/tunelab-realm.json

# ต้องเห็น backend network ที่ stack นี้จะเชื่อมต่อ
docker network ls --filter name=slm-platform_slm-net

สร้าง .env.production บน server:

FRONTEND_PORT=5175
FRONTEND_ORIGIN=https://app.example.com
AUTH_PUBLIC_URL=https://app.example.com/auth
AUTH_DB_NAME=tunelab_auth
AUTH_DB_USER=tunelab
AUTH_DB_PASSWORD=<รหัสผ่าน PostgreSQL ที่สุ่มใหม่และยาว>
KEYCLOAK_ADMIN=admin
KEYCLOAK_ADMIN_PASSWORD=<รหัสผ่าน Keycloak admin ที่สุ่มใหม่และยาว>

# upstream ของ Engine ที่ frontend proxy จะเรียก
ENGINE_UPSTREAM=slm-edge:80
ENGINE_UPSTREAM_HOST=edge
ENGINE_DOCKER_NETWORK=slm-platform_slm-net

# image ที่เพิ่ง push ในขั้นที่ 1
FRONTEND_IMAGE=your-dockerhub-username/tunelab-frontend:20261002.1
chmod 600 .env.production

ขั้นที่ 3 — Pull image และเปิด service บน server

ไฟล์ docker-compose.production.yml ใช้ FRONTEND_IMAGE จาก environment และเชื่อม frontend เข้ากับทั้ง network ของ Keycloak และของ Engine จากนั้นรัน:

cd ~/tunelab-main

# ใช้เมื่อ Docker Hub repository เป็น private
docker login

docker compose -f docker-compose.production.yml --env-file .env.production config --quiet
docker compose -f docker-compose.production.yml --env-file .env.production pull
docker compose -f docker-compose.production.yml --env-file .env.production up -d
docker compose -f docker-compose.production.yml --env-file .env.production ps

# ตรวจ Keycloak และ frontend
curl -fsS http://127.0.0.1:5175/auth/realms/tunelab/.well-known/openid-configuration
docker compose -f docker-compose.production.yml --env-file .env.production logs --tail 100 frontend keycloak postgres
PostgreSQL ไม่ต้องเปิด port ออกสู่ server network ภายนอก เพราะ Keycloak เชื่อมต่อผ่าน Docker network ภายใน

ขั้นที่ 4 — Update และ rollback

หลัง push image version ใหม่ ให้แก้ FRONTEND_IMAGE ใน .env.production เป็น tag ใหม่ แล้วรัน:

docker compose -f docker-compose.production.yml --env-file .env.production pull frontend
docker compose -f docker-compose.production.yml --env-file .env.production up -d --no-deps frontend

หาก release มีปัญหา ให้เปลี่ยน FRONTEND_IMAGE กลับเป็น tag เดิม แล้วรันสองคำสั่งเดิมเพื่อ rollback

ขั้นที่ 5 — ตั้ง backend ให้ยอมรับ Keycloak token

ก่อนใช้งาน Engine จริง backend ต้องใช้ issuer, JWKS และ audience เดียวกัน:

OIDC_ISSUER=https://app.example.com/auth/realms/tunelab
OIDC_JWKS_URL=https://app.example.com/auth/realms/tunelab/protocol/openid-connect/certs
OIDC_AUDIENCE=tunelab-api
AUTH_REQUIRED=true
ถ้า backend เดียวกันยังรับ Supabase token จาก frontend อื่นอยู่ ห้ามสลับเป็น OIDC ทันที เพราะ backend ปัจจุบันเลือกตรวจได้เพียง provider เดียว ต้องแยก backend หรือทำ dual-provider authentication ก่อน การตอบ /health สำเร็จไม่ได้ยืนยันว่า API ที่ต้อง login ใช้งานได้

ตรวจปัญหาที่พบบ่อย

  • pull access denied: login Docker Hub บน server หรือแก้ FRONTEND_IMAGE และสิทธิ์ repository
  • 502 Bad Gateway: ตรวจ ENGINE_UPSTREAM, Docker network และสถานะ Engine
  • login redirect ผิด domain: FRONTEND_ORIGIN และ AUTH_PUBLIC_URL ต้องเป็น HTTPS domain จริง และต้องอัปเดต redirect URI/web origin ใน Keycloak realm ที่สร้างแล้ว
  • ข้อมูลบัญชีหาย: ห้ามใช้ docker compose down -v; volume auth-postgres เก็บบัญชี Keycloak

คู่มือแก้ backend สำหรับ Keycloak/PostgreSQL

ขั้นตอนแก้ JWT verifier, ผูกบัญชีกับข้อมูลเดิม, ทดสอบ และ rollback แยกอยู่ใน คู่มือ backend (Markdown)

เอกสารเก่าด้านล่างใช้ Supabase และ ngrok: เก็บไว้เป็นประวัติเท่านั้น ห้ามใช้กับ frontend รุ่นปัจจุบัน

ติดตั้ง TuneLab Frontend–Backend บน Ubuntu

ห้ามใช้ image เดิมจนกว่าจะ rebuild: image ปัจจุบันฝัง Supabase project ที่ไม่สามารถ resolve DNS ได้ จึง login และ signup ไม่ได้

1. สร้าง Supabase project ของคุณ

  1. สร้าง hosted project ที่ Supabase Dashboard และเก็บ Project ref, Project URL, publishable key และ database password
  2. ใน Authentication → URL Configuration ตั้ง Site URL เป็น https://life-crawling-giver.ngrok-free.dev
  3. เพิ่ม Redirect URL https://life-crawling-giver.ngrok-free.dev/dashboard
  4. ใน Authentication → Providers → Email เปิด signup และ Confirm Email

จากเครื่องที่มี source frontend ให้ apply schema:

supabase login
supabase link --project-ref <PROJECT_REF>
supabase db push --dry-run
supabase db push
supabase migration list

migration สุดท้ายต้องเป็น 20260813000000_disable_demo_user_seed.sql เพื่อไม่สร้างข้อมูล demo ให้ผู้ใช้จริง

2. ตั้ง Google OAuth

  1. สร้าง OAuth 2.0 Client แบบ Web application ใน Google Cloud Console
  2. เพิ่ม Authorized redirect URI เป็น https://<PROJECT_REF>.supabase.co/auth/v1/callback
  3. นำ Client ID และ Client Secret ไปใส่ใน Supabase → Authentication → Providers → Google
Google Client Secret และ Supabase service_role key ต้องไม่ใส่ใน frontend, Docker build args หรือ Git

  --name slm-frontend \

Troubleshooting

docker logs --tail 200 slm-frontend
docker logs --tail 200 slm-edge
docker logs --tail 200 slm-api
docker compose config
docker network inspect slm-platform_slm-net
  • ERR_NAME_NOT_RESOLVED: Project URL ผิดหรือ Supabase project ใช้งานไม่ได้
  • Invalid API Key: frontend ที่กำลังเปิดอยู่ฝัง publishable/anon key เก่าไว้ตั้งแต่ขั้น docker build ให้ build และ push image ใหม่โดยส่ง VITE_SUPABASE_URL, VITE_SUPABASE_PROJECT_ID และ VITE_SUPABASE_PUBLISHABLE_KEY เป็น --build-arg ตามขั้นตอนที่ 3 แล้ว pull และ recreate container ตามขั้นตอนที่ 5; การใส่ -e VITE_... ตอน docker run อย่างเดียวไม่เปลี่ยนไฟล์ JavaScript ที่ build ไปแล้ว
  • redirect URL not allowed: Site URL/Redirect URL ใน Supabase ไม่ตรง ngrok domain
  • 401 invalid token: Backend และ frontend ใช้คนละ Supabase project หรือ JWKS ติดต่อไม่ได้
  • 502 Bad Gateway: frontend container resolve slm-edge ไม่ได้หรืออยู่คนละ Docker network
